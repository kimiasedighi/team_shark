# SwarmRules-v1.0

**Ferienakademie 2026 — Learning Rules for Life-Like Emergent Behavior**

SwarmRules is the shared simulation framework for the course project. The repository/release name is **SwarmRules-v1.0**; the Python module name remains `fa2026`, so student code continues to use `import fa2026 as fa`.

This release contains the shared simulation framework for the first project exercises. The aim is to design **one local rule** that every agent follows and to obtain useful collective behavior from local sensing, memory, movement, pushing, and pheromone communication.

Start with **`getting_started.ipynb`**. It is the main introduction and reference for the student interface.

## Installation

Use Python 3.10 or newer. From the extracted project directory:

```bash
pip install -r requirements.txt
jupyter lab
```

The normal workflow is deliberately small:

```python
import fa2026 as fa


def rule(observation, memory):
    # decide what one agent does in one turn
    ...
    return action, new_memory


result = fa.run("gather", rule, seed=1, visualize=True)
```

Inspect the fixed rules and parameters at any time:

```python
fa.info()          # list available scenarios
fa.info("gather")  # full specification of one scenario
```

`fa.info(...)` includes the goal, geometry, sensing and memory resources, battery/recharge, pheromone decay, cargo mobility where applicable, and the action-energy formulas. It describes the scenario specification without revealing the coordinates generated by a particular seed.

`seed=` changes the randomized initial geometry while keeping the scenario rules fixed. Reusing the same seed reproduces the same task.

## First three scenarios

The first exercises use fixed, deliberately simple parameter sets. You may tune your rule to these scenarios first; robustness to much broader parameter variation comes later.

| Scenario | Goal | Main idea |
| --- | --- | --- |
| `gather` | all agents simultaneously enter the target | exploration and collective guidance |
| `transport` | move one slow cargo into the target | recruitment, positioning, collective pushing |
| `communicate` | move one slow cargo to a target that is initially out of sight | combine exploration, communication, and transport |

The target, cargo position where applicable, and agent positions depend on the seed. A hard-coded global direction therefore does not solve the tasks in general.

All three introductory scenarios have one pheromone channel and 8 memory values per agent. Energy is intentionally permissive so that the first exercises can focus on collective strategy. Cargo mobility is low in `transport` and `communicate`, making recruitment valuable: a few agents can move the cargo, but many well-positioned agents can move it much faster.

## Student interface

Students normally need only:

- `fa.info(...)` to inspect the fixed scenario rules and parameters;
- `fa.run(...)` to run a named scenario;
- `fa.Action(...)` to return an action;
- `fa.Cell.WALL`, `fa.Cell.TARGET`, and `fa.Cell.CARGO` when interpreting local vision.

Each agent receives:

- `observation.energy`: current battery level after recharge;
- `observation.cell_position`: fractional `(x, y)` location within its current grid cell, not an absolute position;
- `observation.vision`: local grid patch containing wall/target/cargo bit flags;
- `observation.pheromones`: local `3 × 3` patch for every pheromone channel;
- `observation.on_cargo`: whether the agent currently lies inside a cargo and can push it;
- `memory`: persistent numeric values belonging only to this agent, initially all zero.

The rule returns:

```python
fa.Action(
    push=p,
    move=(dx, dy),
    pheromones=(q0, q1, ...),
), new_memory
```

All three fields have zero-action defaults. For example, `fa.Action(move=(dx, dy))`
means “move only” and emits no pheromone.

The physical order is **pheromone uptake → push → move → pheromone deposit**. Push is a non-negative scalar; its direction is automatically from the agent toward the center of the cargo it occupies. Movement is a continuous displacement. Negative pheromone values request uptake from the old position before push/move; positive values deposit at the new position after movement.

Movement and push costs are quadratic:

```text
E_move = dx² + dy²
E_push = p²
```

For a pheromone with decay fraction `d`, depositing concentration `q > 0` costs `q/d` energy. Uptake can recover the energy stored in existing pheromone. Batteries recharge automatically every turn.

If the outgoing push/move/deposit request is unaffordable even after uptake, that outgoing package is rejected without spending outgoing energy. Harvested pheromone energy and returned memory are retained. Affordable actions still cost energy even when geometry makes them ineffective.

## Turn order

Each turn is synchronous at the rule level:

1. recharge;
2. observe;
3. evaluate every agent's `rule(observation, memory)`;
4. take up requested old pheromone;
5. accept or reject each outgoing action based on energy;
6. push cargoes;
7. move cargoes;
8. move agents;
9. decay old pheromone and deposit new pheromone;
10. store new memory;
11. test the scenario goal.

Agents do not receive absolute positions, agent IDs, cargo IDs, the number of cargoes, a turn counter, or the complete map. Agents do not directly perceive one another.

## Running experiments

By default a run continues until success or until you interrupt it:

```python
fa.run("gather", rule, seed=1, visualize=True)
```

While developing, a finite safeguard is often convenient:

```python
result = fa.run(
    "gather",
    rule,
    seed=1,
    visualize=False,
    max_turns=500,
)
print(result)
```

The score is simply the number of turns until success. A run that has not succeeded when you stop it is unsuccessful.

## Source and evaluation

The introductory scenario generators are intentionally readable. The exercise is to design collective rules, not to reverse-engineer hidden constants. Later evaluation can use teacher-side seeds and scenario variants that are not distributed with the student package.

To verify the framework locally, run:

```bash
python -m pytest -q
```
